# Borrowed Qoder collaboration proof

`qoder_probe.rs` owns the selected normally logged-in client, private challenge,
installed Skill verification and supervised process lifetime. Qoder reads its
own authentication data. The probe does not import or inspect credential bytes.

`qoder_probe_http.rs` requires a correlated native Skill call, a user-array loaded
Skill receipt, and the exact result of running the selected public HiRoute CLI.
Assistant claims, a string-shaped message, another tool call or file absence
cannot replace these observations. The request and process budgets remain fixed.

On Windows, `qoder_probe_skill_diagnostic.rs` also owns the production retained
Skill binding. Before launch it opens the original directory and `SKILL.md`
without following reparse points, retains their native identities and permissions,
and verifies the entire file digest. It separately proves the canonical name
opens that same directory. Only those two names and their disk-prefix/case
spellings may be queried; UNC, device, stream, parent and foreign paths fail.

One actual user-array text must contain the LF header, an admitted directory and
the exact expected body under the existing outer-whitespace rule. Both sides of
that query must retain the same directory/file identities, single-link file,
the captured Owner/DACL/read-only permissions and original content. These are
before/after observations; they do not claim an immutable lease against arbitrary
transient writes by the same user or unchanged SACL/MIC fields. Missing binding
is a failure.
Linux keeps its exact literal directory receipt rule.

Closed receipt diagnostics are compiled only for tests. Their shape, identity
and body dimensions help explain failures, but they never authorize a match.
Native controls prove ordinary/verbatim equivalence and reject changed content
or permissions, reparse/foreign paths, split candidates and altered message
shapes. Account-free controls do not establish logged-in business acceptance or
upstream provider-account inference.
