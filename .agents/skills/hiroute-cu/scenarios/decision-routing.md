# DECISION: services, branch escalation and observation

Configure decision services through real Desktop, publish smart-saving/custom
branches, and prove actual selection, competence scoring, escalation and session
evidence. Read decision-services, smart-saving-routing and session-history specs.
This extends PLAN/MULTITURN/OBSERVE rather than replacing common assertions.
Use exact Desktop/daemon/CLI, authorized decision provider, at least two business
models, isolated data/task roots and credential references. Real credentials need
normal runtime/CUA; Pilot keeps its no-real-secret boundary. Verify both Debug roles.

1. Two-column service UI: create built-in service, select provider/save, reopen full
   model/endpoint and explicitly test. Failed save can be corrected; cancel leaves
   no partial object. Custom service checks current protocol/curl/OpenAPI, without
   an invented standalone Secret page/CLI hint. Invalid test value fails, repair works.
2. Smart saving: configure economy/primary groups, publish and run simple/complex
   synthetic work through real models/reasoning. Editing standards/competence prompt
   changes only draft until publish. Verify heuristic selection and restore service.
3. Obtain attributable previous-stage scores. Configurable deterministic low-score
   criteria escalate within the same category, retaining branch identity/thresholds,
   up to primary. Each new user message reclassifies difficulty; a simple new round
   without applicable low score returns to economy. Missing/partial scores do not
   preserve old protection or force economy. Tool continuation does not reclassify;
   category/context/Plan revisions do not reuse protection. Never tamper responses/DB.
4. UI creates at least two custom conditions with economy/optional primary and
   independent competence criteria/default failure branch. Hit each with real
   file/tools; verify per-round selection and within-category handoff. Check default,
   copy/recover, single-group no difficulty choice and invalid difficulty retaining
   category/primary. Verify native reasoning, cross-model memory and tool pairing.
5. Publish against service r1; saving r2 does not update the plan until selected and
   republished. Referenced service deletion rejects; unreferenced deletion works.
   Controlled unreachable endpoint verifies failure policy and recovery.
6. Observe the same category, group/candidate, model/reasoning, raw score and lower
   bound in routing performance and session. Missing/partial/zero differ; aggregates
   use full range, not current page. Check current version/last-seven-days defaults,
   below/at threshold/unscored filters. Draft thresholds do not rewrite history or
   later scores the original escalation trigger. Open request and later feedback
   evidence, then restore draft/filter. Screenshots verify layout, not only text.

For each authorized decision provider, test service plus real smart-saving/custom
selection/scoring/escalation. Model randomness, budget, authorization and endpoint
failures stay separate; HTTP 200 is not business correctness. Missing credentials
means not executed. Preserve shortest findings, rerun original failure/affected
consumers after authorized repair and modify only owned objects. Record expectations,
actual result, request/stage/version, screenshots/traces and artifacts in the Issue/PR.
Do not repeat requests or tamper replies to manufacture missing live cases. Changes
to category/difficulty semantics require current criteria, not old escalation evidence.
This remains exploration, not a stable batch business regression.
