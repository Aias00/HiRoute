# PI: native sources, model routing and delegation

Use the exact Mac Desktop candidate, official Pi/compatible Node, authorized
synthetic sources and a dedicated project/HOME/config/data context. No OAuth or
subscription-discovery claim. Read agent-connections, model-discovery,
agent-delegation and worker-platform specs, plus
[Pi evidence boundaries](../../../../tools/product-e2e/tests/PI_INTEGRATION.md).

Minimum smoke scans/imports a provider/model via UI, confirms CLI/Node and Worker
Plan, saves model/task routes, calls saved aliases through ordinary Pi, delegates
an actual task, observes matching task/run/result and restores both facets.
Prepared synthetic sources can support Plan, but scan/import need independent UI
checks. Extend dependencies/protocols with explicit path/repair, lifecycle with
same-session Continue and cancellation isolation, model edits with defaults,
reference-protected deletion and untouched other facets. Never hide rejected
unsupported skills as configured success.

1. Verify SHA, actual window/managed daemon, dedicated roots, applied Debug levels
   and unrelated daily-client PID. Do not manipulate an old/daily instance.
2. Scan a static API source via Models and save/read back real storage. Native
   models/auth stay unchanged; helper/OAuth reports are not imported or executed.
3. Select the saved Pi source explicitly in Plan, enable Pi Worker, confirm CLI/Node
   even for one candidate, use the compatible Node via the install confirmation
   and publish. Detection alone is not confirmation.
4. Use common enable/edit/disable interactions without an extra verification button
   or state. Save selected aliases and only the selected trigger's user Skill;
   changing one facet preserves the other.
5. Ordinary Pi uses provider/model selection without argv/env endpoint/credential
   injection. Verify independent source receipt and upstream model; a real main
   Agent reads installed Skill, calls the public Worker CLI and creates a real file.
6. Desktop shows matching task/run, executor and receipt. Public CLI Continue keeps
   the task/native session with a new run; do not invent a Desktop Continue button.
   For two bounded long tasks, cancel the target via UI and witness its actual child
   stop while the neighbor finishes. Prepare witnesses before a fixture deadline.
7. Disable/recover each facet, verifying original defaults/unknown fields and native
   provider/Skill restoration. Retain only user-requested test state for review.

Read actual visible WebView/Pilot controls, scope duplicate labels to the active
editor, click React checkboxes through events, wait for save and valid confirmation
before navigating. Refresh task list and locate exact task/run before canceling;
confirmation buttons belong to the active dialog. Observe unknown Operations
before resubmission; never repair saves by direct database writes. Only cancel
owned tasks and change synthetic directories. Keep raw diagnosis local, distinguish
product/fixture/environment/expected rejection. This workflow has exploration
knowledge but batch extraction remains pending; fresh package evidence is required.
Real WebView/backend checks do not claim physical-mouse/full-screen capture,
arbitrary live-provider or OAuth acceptance.
