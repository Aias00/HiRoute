# From exploration to batch CU

Read for exploration, trace review or extraction. Codex reviews evidence and writes
ordinary JS; there is no trace compiler, scenario language or new registry.
Run existing repeatable scripts first. For unfamiliar read-only paths, refine
Jev's bounded subgoal/candidates from observations before taking over. Codex owns
writes and business verification; divide a chain instead of expanding Jev's rights.

Keep complete observations/actions locally, including failures, dry-runs and
rejected selections with side effects identified. Direct Codex CU can produce the
same evidence without an artificial Jev call. Read the result and relevant steps
first, expanding to full AX only when needed; do not publish raw traces.

A scenario may combine stable navigation/save fragments, unexplored pages and
Codex business checkpoints. Keep conservative whole-scenario maturity in the
index and fragment status in the scenario. Discovery remains `SKILL.md → index.md
→ scenarios/<goal>.md → scripts/<segment>.mjs`. Document each script's entry,
parameters, assertions and revision; do not load every script or guess its entry.
Reuse loop/driver/trace, one file per coherent reusable segment rather than per
click or run. Link shared fragments. Unverified drafts are not smoke.

1. Verify the original goal, real endpoint and key intermediate states. Distinguish
   Jev completion, completion after prompt refinement and Codex takeover.
2. Replace coordinates/indices with page/region, role and semantic name. Require
   uniqueness; observe again before the next selection.
3. Keep parameters outside the script and preserve checks/invariants. Never embed
   personal paths, credentials or full raw traces.
4. Add local `select` to the existing scenario JS, or a distinct script when the
   responsibility warrants it. Reuse the loop; no per-run regeneration or rollback.
5. Independently rerun from declared prerequisites, including missing/ambiguous
   targets and unexpected pages. Write scripts also need actual business readback.

Repeatable minimum smoke needs verifiable prerequisites/data, semantic locators,
business assertions, safe failure stops, known cleanup/retention and independent
revision-bound rerun evidence. Zero selection, missing state or incomplete calls
fail. An authorized fix first reruns the original failure, then affected smoke.
Formal historical regression cases require [confirmation](cases.md) and run only
when requested. Extraction does not change those business assertions or execution
permissions. Record takeover reason, refinement, resulting script and rerun scope.
