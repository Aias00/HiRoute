# Takeover and improvement

Read after a batch/Jev stop or uncertain result. Observe the actual state before
continuing; never reuse stale indices or blindly replay saves.

- Batch failure returns to Codex. Repair a concrete semantic locator; call Jev
  explicitly only if the read-only path needs exploration.
- One Jev failure warrants trace review and a targeted prompt/context/candidate
  adjustment. Repeated substantive failure, no new basis or exhausted budget
  warrants direct Codex exploration; no repeated sampling vote.
- Writes, sensitive boundaries and uncertain effects require immediate Codex
  reconciliation, without guessing recovery or a mandatory retry count.
- Preserve the shortest product-failure reproduction. Fix/report within current
  authorization; do not encode a defect workaround as the normal path.
- A Jev suspicion is a lead, not a defect verdict. Check expected loading/rejection,
  exploration mistakes, actual defects and insufficient information separately.
  Non-blocking findings can coexist with independent execution; uncertain state
  must be reconciled first. Bounded environment diagnosis keeps unknown causes
  unknown; a successful retry alone does not establish noise.

Continue using the original cumulative budget and completed facts. Wait for
`busy` to clear; only Codex confirmation can clear `needsReconcile`. Read fresh
AX and resume the unfinished goal, preserving the original business baseline.
Raw success/failure traces remain local. There is no general rollback or generated
inverse script. Prefer isolated test objects; use known product cleanup only when
authorized. Unknown recovery stops the affected side effects, not independent
read-only paths.

Preserve the original failure, then rerun its real user entry after an authorized
fix and selected affected smoke. A wording edit, database bypass or successful
retry does not prove the fix. Keep the original criteria. Extract stable steps
only after review and an independent rerun; takeover completion is not evidence
that the newly extracted script passes. Create formal cases under [case rules](cases.md).
