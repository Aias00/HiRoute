# HiRoute implementation supplement

Use `hiroute-implementation-writer` for the assigned change in its current checkout. The same session owns authorized planning, implementation, self-tests, durable SPEC maintenance and returned findings. Delegation requires explicit user authorization.

Read the selected Issue or complete current Design and applicable decisions, then required TASKs, specs, dependencies and relevant code/tests. Confirm the base, ownership, interfaces and checks. Preserve a selected managed lifecycle; ordinary single-writer work needs no additional PROCESS or worktree.

For persisted data, configuration, recovery or published CLI/Gateway changes, use `hiroute-compatibility`. For affected Desktop layout/form behavior, use `hiroute-ui-quality`. Follow `AGENTS.md` for focused checks, final evidence and actual platform coverage. Amend consequential contract conflicts before affected implementation; decide routine private details within the confirmed scope.

Update affected durable specs and their index through the writer's guidance. Keep temporary progress, handoff and validation summaries in the corresponding GitHub Issue/PR; retain raw evidence in ignored local artifacts. Run the public PR check before every authorized public push, including validation pushes.

Return Issue/Design links, base/candidate, checkout, actual checks/results, gaps and shared-file notes for human review. When a coordinated stage was explicitly selected, use that stage's agreed handoff. Do not self-approve or merge peers as an implementation side effect. Repair findings in the same session and report the new head with affected checks.
